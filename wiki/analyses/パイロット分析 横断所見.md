## 横断的発見

### 1. AGENTS.mdサイズを決める要因

```
AGENTS.mdサイズ = f(skillの有無, プロジェクト複雑性, ツール依存度)
```

- **skillなし + 低複雑性** → 6.4KB（about-nishio）
- **skillなし + 高複雑性（ツール開発込み）** → 12.5KB（grasp）
- **skillあり + 低複雑性** → 1.9KB（AMME）

skill層の有無が最大の差を生む。AMMEのAGENTS.md (1.9KB) + skill (18.5KB) = 20.4KB で、実質的な指示総量は他と同等以上。

### 2. index.md/log.md 配置の2派

| 派 | 代表 | 特徴 |
|---|---|---|
| ルート直下派 | about-nishio | AGENTS.mdからの即時参照。`index.md`/`log.md`が`AGENTS.md`と同列 |
| wiki/配下派 | grasp, AMME | wiki/が自己完結。ルートにAGENTS.md+コードのみ |

研究wiki（本repo）はwiki/配下派だが、about-nishioのルート直下配置には「AGENTS.md→index.md→ページ」の参照パスが1段短い利点がある。テンプレートとしてどちらを推奨するかは要検討。

### 3. AGENTS.md=CLAUDE.md 管理の3パターン

| パターン | 例 | リスク |
|---|---|---|
| 完全コピー | about-nishio | 同期漏れリスク（実際にCLAUDE.mdのみ更新指示あり） |
| 共通部分コピー+差分分離 | grasp | 二重メンテナンス（共通部分の変更時に両方更新必要） |
| CLAUDE.mdなし | AMME | opencodeのみ使用のため不要 |

テンプレートとしての推奨: 単一AGENTS.mdを基本とし、ツール固有の差分は `.claude/`, `.opencode/` 等に分離する。symlinkやコピーは避ける。

### 4. メタデータ戦略のスペクトラム

```
frontmatterフル（type+summary+sources+tags+dates+status）
  → about-nishio, grasp

frontmatter最小（source: 行のみ）
  → AMME-2026S-report

frontmatterなし
  → （AMMEのconcept/entityページ）
```

AMMEは100ページ・785リンクのwikiをfrontmatterほぼなしで運用できている。
ただし3週間・単一ユーザーという条件付き。長期・多人数ではfrontmatterによるstatus/tags管理が必要になる可能性が高い。

### 5. wikilinkなしでもwikiは成立する

AMMEは `[[wikilink]]` を1つも使わず、標準Markdown相対リンク `[text](../path/file.md)` のみで785リンクを実現。
index.mdのHTMLテーブル形式カタログがバックリンク機能を代替。
この発見は [[テンプレート草案ver.1]] claim#8「wikilinkを本文中に書くべき（first-class）」への反証データ点となる。

### 6. purpose-hoist: 目的明示の価値

about-nishioの事例: 目的不在による迷走 → ユーザー指摘 → AGENTS.md冒頭に目的セクション追加 → 収束。
このパターンはAGENTS.mdテンプレートに「目的」セクションを必須化する根拠となる。

### 7. log.md爆発と自動化の相関

| repo | log.md | file-back自動化 |
|---|---|---|
| about-nishio | 313行 | 手動 |
| AMME | 336行 | 手動 |
| grasp | **2,018行** | 自動（ship loop） |

file-backの自動化がlogの爆発的増加を引き起こす。テンプレートにlog肥大化抑制ルール（例: 1回のfile-backで最大N行まで）が必要。
