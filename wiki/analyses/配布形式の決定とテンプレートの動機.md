# 配布形式の決定とテンプレートの動機

2026-08-14の議論（subagent相談2往復込み）で固まった、テンプレートの**動機と配布形式**の決定。
研究課題「配布形式はどうするか？」（[[このWikiの目的と研究課題]]）への暫定回答。

## テンプレートを作りたい動機

1. **お決まり経路の再発明防止**: llm-wiki.md gistをコピペしてLLMに立ち上げさせればwikiは動く。しかしAGENTS.mdの作成・wiki/の立ち上げ・frontmatter形式・log形式の決定は、どのwikiでもほぼ同じ経路をたどる。毎回llm-wiki.mdから立ち上げさせるのは面倒。しかもllm-wiki.mdはAGENTS.mdができたら不要になるため、消す作業が要る
2. **立ち上げ品質のばらつき対策**: llm-wiki.mdからの立ち上げは、その時のcontextや使用LLMによって結果が揺れる（いまいちなwikiになることも、たまたまうまいformatが組み立てられることもある）。うまいやり方をあらかじめtemplateに入れ、試行錯誤の手間を省きつつ、いまいちな方向に進まないよう**お膳立て**したい

## 決定: 配布形式はtemplate/コピペ方式

- このrepoに `template/` ディレクトリを作り、**その中身を新規wikiのrootディレクトリに手動コピペすればそのまま動かせる**形にする
- 配布機構（別repo / GitHub Template Repository / `npx create-llm-wiki` 等）は想定しない。手動コピペ前提
- 方向性: 「文書（AGENTS.md指示）でツール非依存・選択自由」は含まれるが**メインではない**。メインは「**お膳立て（bootstrapの品質保証）**」
- **template/内には動機を記載しない**（2026-08-14決定。動機の記録はwiki側のみ）
- 前回のconsultation（2026-08-14 adopt | MCP不採用）が推奨していたGitHub Template Repository配布は、この決定に置き換わる（[[MCP不採用とAGENTS.md+SKILL.md二層採用の根拠]]）。GitHub Template Repositoryは「別repo前提」のため、手動コピペのtemplate/併置とは排他関係にある

## subagent相談の結論（妥当性検証）

### 妥当性の条件: 「最終状態ファイルのコピー」であり「init指示のコピー」ではない

- 揺れへの効果は本質的: template/が「完成状態のファイル群」を固定し、bootstrap時にLLMが構造を発明する余地を消す
- init指示（bootstrapプロンプト）の同梱はdeliteのinit.txtパターン（[[リポジトリ分析 llm-wiki-about-delite]]）の失敗——誤記の二重管理と削除作業——が再発する。**「llm-wiki.mdを消す作業」が消えるのは、template/が起動指示ファイルを持たない場合のみ**
- テンプレート可能/不能の境界: 目的の言語化と最初のingest対象（種）の選定は人間に残る（[[パイロット分析 横断所見]] のread-involved実測）。テンプレートにできるのは「機械的作業のゼロ化 + 判断作業の導線明示」まで。この境界線の明示自体が設計成果物

### 2往復目の修正4点（合意）

1. **claims対応表は2軸に**: 「記述的検証結果 × 規範的決定」。claim#7（read-optional）は「記述=反証（5/5 read-involved）/ 規範=未決」の2セル。**未決のままデフォルトは決められる**（read-involved前提の可読性最小保証。失敗コストの非対称性が根拠: read-optional想定で作って実は読まれる→サイレント失敗 vs 可読性想定で作って実は読まれない→軽微なオーバーヘッド）
2. **「検証済みclaimsのみ焼き込み」は撤回、文種4分類に**: templateの中身は ①実証済み知見（3層構造・indexカタログ・purpose-hoist・赤リンク参照数分割lint） ②お決まり経路（このrepoで毎週実践中のingest/query/file-back/lint/log形式。**自己適用こそ最大の検証**） ③多数派デフォルト（index/log配置 4/5・自然言語命名 3/5・wikilink 5/6） ④研究repo固有（不採用: 「実験台」「仮説status遷移」等の文言は他wikiで毒になる）。claims対応表は**追跡器であって生成器ではない**
3. **v0.1検証は1モデル×2回+lint+構造diff**: 揺れ低減の主張は「固定範囲の遵守」でありtemplateとのdiffで検証可能。2回目はほぼ無料で「templateが決定的なのか、そのモデルが偶然従ったのか」を区別できる。2 LLM×2目的の横断検証はM2（外部boot成功後）に繰り下げ
4. **customization points撤回: 設定事項0・記入事項1（purposeのみ）**: 分類数・wikilink可否・repo型はbootstrap時決定にしない。**解釈余地はbootstrap時にゼロ**。運用後に痛みが実証された時（例: リンクが疎で気になる）にだけ参照するvariant guide（変種ガイド）に移す（YAGNI。[[事前にやろうとしない運用哲学]]と整合）

### 他の合意事項

- **ドリフトは同期機構を作らず許容**: コピペ方式は「各wikiが独立フォーク」になることが仕様。templateにバージョン+日付の1行記載、破壊的変更時のみmigration note。**研究repoへの後方適用はしない**（実験の測定器を撹乱しない。実際2026-08-11にAGENTS.mdが2回変更済み）
- 形式例（frontmatter・logエントリ・index行）はAGENTS.mdの**インラインコードブロックのみ**。サンプルページ同梱は「消す作業」の小さな再発になる
- 研究repoの文言（「実験台」「仮説はwiki側に移管」等）はtemplateに絶対コピーしない。templateは**派生物**であり複製ではない（[[LLM Wikiの作文リスク]]の複製ドリフト対策と整合。意図的な一次複製として例外記録が要る）
- lint.shは研究repo特化チェック（sourcesページの`raw:`必須等）を外したtemplate版が必要
- raw/は**追跡デフォルト**（現repoの.gitignoreは例外構成の実証例。[[rawディレクトリの取り扱い]]）
- `npx create-llm-wiki`は**戦略ミスマッチで却下**: 操作層のツール化=[[Microsoft llmwiki]]の方向と反する。開発・メンテ・versioningコストも最大。外部利用者が10人以上bootstrapした実績が出るまで維持
- 別repo切り出しはM3マイルストン（研究の完了定義「テンプレートがこのwikiから分離し」の文字通りの最終形）

## template/ v0.1の内容スケッチ（subagent案）

```
template/
├── AGENTS.md          # 本体。コピペしてpurpose1行を書けば動く
├── README.md          # コピー手順・最初の30分（初期導線）・variant guide・バージョン/migration note
├── .gitignore         # 最小限（raw/は追跡デフォルト）
├── scripts/lint.sh    # 機械チェック（任意。READMEに明記）
├── raw/               # manifest + .gitkeep（ヘッダ+追記指示のみ。形式例はAGENTS.mdに）
└── wiki/              # index.md / log.md / overview.md / concepts/ entities/ sources/ analyses/ の空骨格
```

AGENTS.md骨格（9セクション）:
`目的（purpose-hoist。唯一の記入事項）/ アーキテクチャ（3層）/ ディレクトリ構成 / ファイル命名 / 執筆の機械要件（インライン形式例）/ 初期化（初回のみ。delite init.txt教訓: 指示をAGENTS.md本体に置き二重管理を排除）/ オペレーション（Ingest/Query/Lint/File-back）/ よくあるパターン（最小2-3件）/ バージョン`

形式例はサンプルファイルでなくAGENTS.mdのインラインコードブロックで提示。

## bootstrap成功基準（QAゲート、2段階）

- **Stage 0（人間・セットアップ）**: templateコピー+git init / AGENTS.mdのpurpose記入（空欄のままなら不通過）/ variant guideを読んだ痕跡をlog.mdに記録
- **Stage 1（LLM・初回bootstrap。機械検証可能）**: tree diffで構造一致性 / AGENTS.mdセクション骨格一致 / 初回ingest完走（raw→sources→concepts/entities→index→log）/ log形式一致 / sourcesページの`raw:`必須 / `scripts/lint.sh`合格 / **同一モデル×2回目でも再現**（determinismチェック）
- **Stage 2（初回1週間。縦断的）**: 人間がquery→初回file-back発生 / 2回目のingestが同じ手順で完走しlog形式がdriftしない / 別モデルの実wikiがもう1つ同基準を通過（M2）
