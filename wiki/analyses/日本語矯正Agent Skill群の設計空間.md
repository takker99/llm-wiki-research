# 日本語矯正Agent Skill群の設計空間

OSSコミュニティの日本語文体・語彙矯正Agent Skill群を、LLM Wikiテンプレート設計の観点から整理した分析。出典は[[2026-10-27 低コストLLMの日本語矯正とスキル設計]]の8スキル構造分析。[[このWikiの目的と研究課題]]の「AGENTS.mdには何を書くべきか」「テンプレートに何を同梱するか」に直接答える素材。

## 設計空間の2軸

スキル群は「対象とする言語学的階層」と「検査アーキテクチャ」で分化する。

| スキル | 主な矯正レイヤー | 検査・スクリプト層 | 設計メカニズムの核心 |
|---|---|---|---|
| yomiyasu | 主述・動作主の復元、名詞過剰圧縮の展開 | Python標準ライブラリlint＋SHA-256実行証明 | 7変換原則、文書種別×読者知識3段階の保護、6項目言い直しテスト、allow/flag語彙管理 |
| japanese-tech-writing | パラグラフライティング、論証の厳密さ、定訳厳守 | なし（プロンプト規範＋reference群） | 因果メカニズム明示、概念初出の「種類・地位」前置、推論に委ねる短文化の禁止 |
| natural-japanese | 文長リズムの均質性打破、翻訳調・冗長表現 | Python＋SudachiPy形態素解析（lint.py等） | 人間137本・AI 406本のコーパス実測で閾値校正、「検出は機械・判断はAI」の分離 |
| suiko | 表層パターン、形態素品詞列、統計的リズム | Rust単一バイナリ（1秒未満） | 検出層のRust化、preimage一致確認による安全な部分縮約 |
| stop-ai-slop-jp | 書き手の立場、False Agency排除、造語除去 | なし（SKILL.md＋references） | 「立場→主体→構造→語彙→記号」の修正優先順位、二項対比の排除 |
| japanese-humanizer | 6領域分類（翻訳調・冗長・係り受け等） | Node.js | 「意味不変・不増補・ジャンル保持・過剰修正禁止」の4約束とP1-P3優先度の段階的修正 |
| meiseki | 中立的明晰化 | 機械検出＋LLM推敲 | 書き手の声を足さず仕様書の明晰さを高める（一人称注入型との対極） |
| 綴文子等 | 評価→清書→再確認の3段階検証 | textlint ASTルール等 | 多段階適用、忠実さ（F）と自然さ（N）のトレードオフ管理 |

## 観察された設計原則

1. **検出と判断の分離**: 機械リンターが確実に捕捉するのは表層（「〜することができます」「大幅に」等の冗長表現・曖昧な程度副詞・文長リズム）。無生物主語の擬人化（False Agency）や「単なるAではなくB」等の構造的AI構文は、主述・構造レイヤーを明示的に監査するスキルでないと捕捉できない
2. **無制約な推敲は事実を壊す**: 短い推敲プロンプトの単体実行（Gemini提供稿）では16稿中8稿が因果捏造や「予定→決定」書き換え等の改変を起こし、忠実さ（F）が-0.938悪化。natural-japaneseのように自然さ（N）を+0.406向上させるスキルでも忠実さがわずかに低下（-0.062）する
3. **モグラ叩き**: 単語の単純禁止では別の不自然な表現へ逃げる。「病理の説明＋対比書き換え」のセットが必要 → [[語彙接地（Lexical Grounding）]]
4. **忠実さと自然さのトレードオフ**: 正確性最優先の用途では「事実・条件・確信度を変えない範囲でのみ構造を展開する」制約を最上位に置く

## テンプレート設計への含意（仮説）

- **同梱するライティングskillの選定軸**: 本wikiの用途（研究wiki・出典追跡・低コストモデル運用）では忠実さ最優先。構造展開型（yomiyasu・japanese-tech-writing系）＋事実保持制約が候補。一人称注入型（stop-ai-slop-jp系）は「書き手の声」が必要な文体用途向けで、wikiページの書き込み用途には過剰
- **AGENTS.mdに載せる絶対ルールの候補5項目**（300-400トークン以内）: 漢字5文字以上の造語禁止／原語・定訳優先とindex照合／「の」連鎖と体言止めの制限／事実・確信度の不変／スキルルーティング1行。サイズ根拠は[[Instruction Dilution]]
- **lintスクリプトの設計原則**: 自動置換せず「箇所の指摘＋実行証明ハッシュ」に特化する。allow/flagリストを外部化しドメイン依存の語彙を分離できる。[[Lint]]の機械検査の射程設計に接続
- **6項目言い直しテスト・対比例文の配置**: SKILL.md本体に載せるかreferencesに退避するかは、トークン上限（5,000未満）との兼ね合いで決める → [[AGENTS.md+SKILL.md二層設計]]
- 規約文書自体の文体が手本になる問題は[[プロンプト自己言及汚染]]
