# 操作層

wikiに対する操作（ingest・query・lint・file-back等）を定義・実現する層。
OKF議論でnishioが成果物（format）層と区別して用いた語:
「OKFはformat層のみ標準化し、操作層を標準化しない——テンプレートは操作層（AGENTS.md）を提供する点で差別化可能」
（[[2026-08-11 OKFとLLM Wiki (nishio+villagepump)]]、[[nishioのOKF評価]]）。

format層（ファイル構造・frontmatter・命名）と操作層（どう運用するか）を混同しないことがテンプレート設計の前提。

## 実現手段のスペクトラム

| 手段 | 例 | 特徴 |
|---|---|---|
| **文書型**（AGENTS.md指示） | Karpathy・nishio・本wiki | ツール非依存・自由・実装コスト0。誤りは[[Lint]]で回復 |
| **ツール型**（MCP/CLI/拡張機能） | [[Microsoft llmwiki]] | 決定的実行・安全検証・メトリクス可能。モデル/IDE依存・開発コスト |

両者は排他ではない。AGENTS.mdに操作指示を持ちつつ、一部操作をツール化する混在も可能。

## ツール型の制度化事例（Microsoft llmwiki）

- MCPサーバ14ツール: `wiki_read_page` / `wiki_write_page` / `wiki_create_entity` /
  `wiki_add_crosslinks` / `wiki_ingest_with_context` 等。操作の全セットが関数化
- write系に安全モデル: path traversal防止・frontmatter必須（title+type）・index upsert・エラー分離
- file-backがコマンド化（`@wiki /save`）、lint/status（coverage %）が機械実行化

→ 詳細は [[リポジトリ分析 microsoft-llmwiki]]。

## 文書型の制度化事例

- 各wikiのAGENTS.md（本wiki含む）の Ingest / Query / Lint 操作ステップ
- 操作の「決定的実行」はできないが、[[AGENTS.md+SKILL.md二層設計]]のように手順を構造化して精度を上げる

## テンプレートへの示唆

- 操作層の提供方法（文書 vs ツール vs 両方）は配布形式と直交する設計軸
- 「操作層をどう実現するか」が既存実装との差別化の主戦場（[[このWikiの目的と研究課題]]）
