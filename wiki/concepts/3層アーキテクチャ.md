# 3層アーキテクチャ

LLM Wikiの基本構造。Karpathyが定義する3つの層:

1. **Raw sources（`raw/`）** — 人間がキュレーションした生のソースドキュメント群。論文、記事、画像、データファイル。Karpathyは「**不変**。LLMは読むだけで、決して変更しない。これがソース・オブ・トゥルース」と定義する。実際の運用では「不変」はソースの性質ではなく**入場時の誓約**として再解釈される: raw/に書き込んだ時点の内容で凍結され、以後はアーカイブの新規追加と `raw/manifest.md` への追記のみ許可（append-only）→ [[rawディレクトリの取り扱い]]

2. **The Wiki（`wiki/`）** — LLMが生成したMarkdownファイルのディレクトリ。要約、実体ページ、概念ページ、比較、俯瞰図、総合。LLMがこの層を完全に所有する。新しいソースが来ればページを作成・更新し、相互参照を維持し、一貫性を保つ。人間は読む、LLMは書く。

3. **The Schema（[[Schema（AGENTS.md）]]）** — LLMにwikiの構造・規約・ワークフローを伝える設定ドキュメント（例: `CLAUDE.md`、`AGENTS.md`）。LLMを「しつけられたwiki保守者」にするための鍵。人間とLLMが共進化させる。

## 設計上のポイント

- `raw/`と`wiki/`の分離により、wikiの事実が争われたら`raw/`まで遡って検証できる
- 不変性の機能は3つに分解できる: 検証可能性（争われたら遡れる）・書き換え自由の担保（wiki/の自由な更新を可能にする）・LLMの範囲境界（ソースに手を加えさせない）→ [[rawディレクトリの取り扱い]]
- **価値の中心は knowledge network**: 3層構造は**補助装置**であり、LLM Wiki の main value は wiki/ の中で育つ knowledge network 自体にある（[[LLM Wikiのmain value]]・[[raw SSOT原則への根本検証]]）。raw/ の検証可能性・作文リスク防御・LLM 範囲境界はいずれも knowledge network の信頼性を支える**補助機能**にすぎない
- Schemaはパターンを伝えるだけの抽象文書（Karpathy gist本体）と、具体的な運用ルール（各wikiのAGENTS.md）の2層に分かれる → [[LLM WikiテンプレートのOptionality]]
- この構造は当wikiにも採用されている → [[テンプレート草案ver.1]]
- nishioの実践: [[Wikiはワークショップ]] — wikiをsource of truthにしないことで動的合成層として機能させる。[[Vault分離と人間-AIの境界]] — AI用Vaultと人間用Vaultの分離は3層構造の延長線上にある
- tsurubeeの実践（2026-08-11 ingest）: 三層構造の再確認のみで新規性なし。ただしミニマム構成の実例（CLAUDE.md + 4スキル + vault/）を提示 → [[LLM WikiテンプレートのOptionality]]
- **Microsoft llmwikiの独立収束**（2026-08-14 ingest）: Karpathyと独立に同一の3層構造（`raw/`/`wiki/`/AGENTS.md）を実装。index.mdカタログ・log.md追記の形式も当wikiとほぼ同一 → 構造の普遍性の強い証拠。差異: wiki rootを `.wiki/` サブディレクトリに埋め込む（プロジェクト内wiki、同一repo型の一形態）。→ [[リポジトリ分析 microsoft-llmwiki]]
