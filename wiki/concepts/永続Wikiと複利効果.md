# 永続Wikiと複利効果

LLM Wikiの中核的な差別化ポイント。通常のRAG（[[NotebookLM]]、ChatGPT file uploads等）はクエリ時に生ドキュメントのチャンクを検索し回答を生成する。これは「毎回知識をゼロから再発見する」モデルであり、5つのドキュメントを横断する微妙な質問には毎回断片を探し集める必要がある。何も積み上がらない。

対して永続Wikiは:
- 知識は一度コンパイルされ、最新に保たれる（再導出不要）
- クロスリファレンスはすでに存在している
- 矛盾はすでにフラグされている
- 合成知見はすでに読み込んだすべてを反映している
- ソースを追加するたび、質問するたびにwikiは豊かになっていく

これをKarpathyは **"compounding artifact"（複利的に成長する人工物）** と表現する。100個目のソースはすでにある99ページに接続される。価値は単一の完璧な要約からではなく、ネットワークの蓄積から生まれる。

nishioによる[[LLM Wikiは要約の改良版ではない|別角度からの説明]]: LLM Wikiは情報を圧縮しない。猫の医療記録135KB→143KB（1.06倍）。代わりに[[注意の足場]]を作り、入口→用語集→詳細の階層で認知負荷を下げる。要約は1回ごとに使い捨てだが、LLM Wikiは続く。要約を100回別々に作っても起きない現象がcompounding。

## 複利の裏面（2026-10-27 ingest）

複利は符号を持たない。ガバナンスのない自己消費ループでは、正しい統合ではなく歪んだ要約が次世代の入力となり、劣化が複利で増幅する。100個目のソースが既にある99ページに接続される力は、99ページの歪みが100ページ目に伝播する力でもある → [[自己消費ループ]]

防衛線はwiki側の構造にある: raw/不変層からの再読（可逆性の担保）、出典切断のない上書き、[[Lint]]による陳腐化検出。
