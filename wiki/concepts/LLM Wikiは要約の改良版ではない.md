# LLM Wikiは要約の改良版ではない

nishioによるLLM Wikiの本質を端的に表す概念ページ。Karpathy gistにはない切り口。

## 1. 圧縮していない

実測: 猫の医療記録135KBをLLM Wiki化→143KB（1.06倍）。情報量は減っていない。代わりに注意の足場を作っている:
- 家族が読める1枚（overview）= 全体の12.6%
- 用語集（検査値9個＋病態4個）= 累積43.7%
- 時系列、詳細 = 100%

入口ページに注意を集中させるので認知負荷は劇的に下がる。「圧縮しない要約」の正体。

## 2. 要約の構造的5問題

1. 抽象化が経験と切断する — 人間の知識のアンカーは具体側にある
2. 書籍は既に抽象化産物 — 要約すると二重抽象に
3. 専門用語を一般語に丸める — 解像度が落ちる
4. 平均的読者を想定 — 学習は一歩先でしか起きないのに
5. ストーリーの配列が壊れる — 断片自体に価値がある前提

## 3. LLM Wikiは構造で答える

- 抽象化での切断 → conceptからraw/への着地パス
- 専門用語の喪失 → conceptページで原型保持
- ストーリーの破壊 → raw/でナラティブ温存
- 平均読者ずれ → 既存wiki群自体が「あなたの知識マップ」

## 4. 蓄積する

要約は1回ごとに使い捨て。LLM Wikiは続く。100ページ目をingestする時、AIは既存の99ページと結びつく箇所を探す。要約を100回別々に作っても起きない現象。
