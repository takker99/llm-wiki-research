# 理解のボトルネック

tsurubeeがLLM Wikiの1ヶ月運用で見出した限界。LLMが概念ページを綺麗に整理しても、人間が読んで自分の理解として消化しないと「自分の知識」にならない、という問題。

## 記事の主張

- 研究のアイデア・論文・議論で最終的に頼りになるのは自分の頭の中の理解
- 対策1: ソース選定は自分の手で行う（量より質）。自動ingestを避ける理由は「いつの間にページができたんだ」状態で理解のボトルネックが深刻化するから
- 対策2: wikiの使い方を二分する——(1)辞書的使い方（queryして回答を得るだけ）=「LLMに外部記憶を完全委託した状態」と警鐘、(2)理解の補助（概念ページを能動的に読み再構成）。後者を推奨するが、網羅的キャッチアップは未解決

## ⚠ Contradiction: [[読まれなくてよい中間産物]]と対立

| | nishio（読まれなくてよい中間産物） | tsurubee（理解のボトルネック） |
|---|---|---|
| 読む主体 | 一次読者はLLM（Query）へ移行。人間は読まなくてよい | 人間が読んで理解しなければ知識にならない |
| 読みやすさ | 中間産物は読みにくくてよい | 概念ページは「自分が読み返したい形」に育てる |
| 中間産物の扱い | 最終産物（エージェントの振る舞い）のために存在 | 読まれること自体が目的の一部 |

nishioの実践（「新規作成・更新されたものを逐一読むことはしない」）とtsurubeeの実践（時間を見つけて概念ページを読み返す）は運用でも正反対。

## nishioによる直接の回答: 知識のネットワークは外側にあればよい

勉強会の講義資料（`raw/nishio-KarpathyのLLM_Wiki勉強会.md` L177-196）に、この問いへの実質的な回答がある:

- 検索時代（A）: 複数ドキュメントを読むことで個人の中に知識のネットワークが育つ
- Deep Research以降（B）: 整理済みドキュメントを「1回さらっと読んだだけでは知識のネットワークが育たない」。結局何度も読み、重要なものが繰り返し出現することで定着していく
- **「LLM Wikiは、この『知識のネットワーク』を人間の外側で作っている」**（L189）
- [human.icon]「人間の中に知識のネットワークができにくくなるのは、まあ大した問題にならない？」に対するnishioの回答:
  - 「確かに何かを成し遂げる上で、AIが全部の作業をするのであれば、究極人間の中に知識のネットワークが構築されなくても目的が達成されることはあり得る」
  - **「その『目的』が目的であり、『人間の中に知識のネットワークができること』は従来型の目的達成の手段にすぎない」**
  - ただし人間の「目的」や「期待」はAIに分からないので、人間が言語化して伝える必要がある。**AIとの対話が目的の言語化の支援になっている**

つまりnishioは「理解のボトルネック」を手段の置き換えとして解消し、人間に残る不可分な役割を「全ソースのキャッチアップ」ではなく「目的の言語化」に再定義する。

## 手段の目的化の問い直し（このwikiの考察）

nishioの回答はさらに一般化できる: **「自分の頭の中の理解」はあくまで目的達成の手段であり、必ずしも目的でも必須の手順でもない**。

- 研究を例にすると、最終的に必要なのは研究成果であり、研究者自身がどれだけ理解しているかは本来無関係
- もっとも、研究発表や他の人に研究内容を聞かれたときに答えられなければならないケースでは、頭の中で理解している必要が生じる（発表という目的が理解を必須の手順にする）
- したがって問い直すべきは「頭の中で理解する、という手段が目的化していないか？本当に必要か？」であり、この問いによって「読むべきか・読まなくてよいか」の答えは場合分けされる

この視点はtsurubeeの「最終的に頼りになるのは自分の頭の中の理解」という前提そのものを前提でなくす: 理解の必要性は「その後に人間が何をするか」で決まるのであって、wiki運用の普遍的条件ではない。

## テンプレート設計への含意

この対立は研究課題「汎用AGENTS.mdに何を書くべきか」への重要なインプット:
- read-optionalをデフォルトにするか、人間が読む前提の可読性設計（例: overviewの重視）にするかは未解決
- 当wikiはnishio系のread-optional寄りで運用しているが、[[テンプレート草案ver.1]] claim#7（人間はwiki/を読まなくてよい）の検証データとしてこの対立を記録すべき
- ソース選定の手動主義は「読む前提」の帰結であり、read-optional派の[[バッチIngest]]・[[AIによるingest停止判断]]と対になる
