# Lint

wikiの健全性チェック。ユーザーの明示的な依頼で発動する。
機械チェックはスクリプト（決定的）、意味チェックは読解（LLMの判断）で行う。

## 手順

1. 機械チェック: `bash .agents/skills/llm-wiki-lint/scripts/lint.sh` を実行する
   - 孤立ページ（他のwikiページからの入リンクがない。ただし sources/ は index.md 掲載を消化判定とする——排掲載 = 未消化ソース）
   - 未解決の `[[wikilink]]`（オープンリンク。リンク先ページがまだないリンク）— 参照数で扱いを分ける:
     - **1ページのみ参照** — 表記ゆれ・パス形式・未作成ページのいずれかを確認する。意図的な前方参照なら放置し、ページを作らない
     - **2ページ以上で参照** — 仮想ページ／概念ハブの種。欠陥ではない。ページ作成の候補として人間に提案
   - index.md に載っていないページ
   - indexエントリが指すファイルが存在しない（stale） — ページ削除・リネーム後のindex残骸。陳腐化時はページを読み直して再生成してよい
   - wiki/ が参照している raw/ ファイルが実在しない
   - sources/ ページが frontmatter に `raw:` を持たない
   - 同一ページ内の重複 `[[wikilink]]` — claim粒度引用（`p.XX` の引用箇所違いの反復）は免除。ページ番号なしの裸反復・同一箇所の反復・関連節での再掲は除去対象
2. 意味チェック（手動）:
   - ページ間の矛盾（同一トピックで衝突する主張）
   - 古い主張（新しいソースに取って代わられたもの）
   - ページに言及されているのに概念ページが存在しない概念
   - 明らかに関連するページ間のクロスリファレンス不足
3. 新しい調査課題と探すべきソースを提案する。ingest時の未カバー領域指摘が溜まっている場合はそれも材料にする
4. 重大度別に報告し、機械的な問題の自動修正を申し出る

## 注意

- オープンリンクは欠陥ではなく設計（情報の不在＝未来への接続点）。lintに出ても「壊れている」と報告しない。1参照は表記の確認、2+参照はページ作成の提案として扱う
- lint結果の解釈はLLMが行う。スクリプトの出力をそのまま報告するだけでなく、優先度をつけて伝える
