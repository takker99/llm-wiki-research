# Lint

wikiの健全性チェック。ユーザーの明示的な依頼で発動する。
Lintは**診断（read-only）→トリアージ→治療（承認後）**のワークフロー。機械チェックはスクリプト（決定的）、意味・構造チェックは読解（LLMの判断）、治療は `.agents/skills/llm-wiki-write/SKILL.md` に従う。

## 手順

1. 診断: `bash .agents/skills/llm-wiki-lint/scripts/lint.sh` を実行する。診断中はファイルを書き換えない
   - 孤立ページ（他のwikiページからの入リンクがない。ただし sources/ は index.md 掲載を消化判定とする——排掲載 = 未消化ソース）
   - 未解決の `[[wikilink]]`（オープンリンク。リンク先ページがまだないリンク）— 参照数で扱いを分ける:
     - **1ページのみ参照** — 表記ゆれ・パス形式・未作成ページのいずれかを確認する。意図的な前方参照なら放置し、ページを作らない
     - **2ページ以上で参照** — 仮想ページ／概念ハブの種。欠陥ではない。ページ作成の候補として人間に提案
   - index.md に載っていないページ
   - indexエントリが指すファイルが存在しない（stale） — ページ削除・リネーム後のindex残骸。陳腐化時はページを読み直して再生成してよい
   - wiki/ が参照している raw/ ファイルが実在しない
   - sources/ ページが frontmatter に `raw:` もしくは `source_url:` を持たない
   - 同一ページ内の重複 `[[wikilink]]` — claim粒度引用（`p.XX` の引用箇所違いの反復）は免除。ページ番号なしの裸反復・同一箇所の反復・関連節での再掲は除去対象
2. 意味チェック（read-only）:
   - ページ間の矛盾（同一トピックで衝突する主張）
   - 古い主張（新しいソースに取って代わられたもの）。rawに戻って確かめる必要があるものはre-ingest候補にする
   - ページに言及されているのに概念ページが存在しない概念
   - 明らかに関連するページ間のクロスリファレンス不足
   - index.md の要約がページ本文とずれていないか（要約内容の陳腐化はここで見る。エントリの欠損・参照切れは機械チェック）
3. 構造チェック（deep lint・read-only）:
   - 同一概念の重複ページ・表記揺れ
   - 肥大化ページの分割候補、小さすぎるページの統合候補
   - リンク密度・孤立ハブ・クロスリファレンスの偏り
   - 命名の一貫性（用語集・aliasとの照合）
   - ディレクトリの偏り（analysesの肥大化など）→ 株分けの提案
   - routineでは省略してよい。月次か、ingestがN件溜まった時に実行する
4. トリアージ: 検出結果を次の4つに分類する
   - **機械修正** — リンク切れ、表記統一、重複リンク除去
   - **リファクタ** — 統合・分割・rename・節の移動・リンク修理。意味を変えない構造変更
   - **re-ingest** — 古い主張・矛盾の解消。意味を変えるのでrawに戻る
   - **成長提案** — 新しい問い・探すべきソース
5. 治療（承認後）:
   - 承認された項目だけ、write SKILLに従って適用する。1リファクタ1コミット
   - 意味を変える変更はre-ingestとして扱い、Lintの治療で直接書き換えない
   - 分割は移動ではなくコピーとして提案する
   - 適用後にlintを再実行し、`wiki/log.md` に `lint` エントリを追記する
6. 重大度別に報告する。診断結果と治療計画を分けて示す

## 注意

- 診断中は書き換えない。検出と適用を同じパスで混ぜない
- リファクタは意味保存、re-ingestは意味変更。この線引きがないと、Lintが「構造の整理」の名目で知識の内容を変えてしまう
- オープンリンクは欠陥ではなく設計（情報の不在＝未来への接続点）。lintに出ても「壊れている」と報告しない。1参照は表記の確認、2+参照はページ作成の提案として扱う
- `https://`や`#`を含む`[[wikilink]]`はスクリプトで解決できない — 実見時に手動確認としてよい
- lint結果の解釈はLLMが行う。スクリプトの出力をそのまま報告するだけでなく、優先度をつけて伝える
